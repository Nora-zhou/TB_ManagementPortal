# Feature Specification: 商品详情页订单实付价格走势

**Feature Branch**: `005-product-order-price-trend`

**Created**: 2026-05-26

**Status**: Ready for Planning

## Overview

在商品列表页进入商品详情页后，新增一个价格走势图区域。走势数据来源于已导入的淘宝订单（子订单格式），通过 `商品ID` 精确匹配商品，提取该商品的顾客实际支付金额（买家实付金额），按时间维度整理成价格走势，供卖家判断商品实际成交价格变化趋势。本功能扩展现有商品详情页，与已有的「快照价格走势」**并列展示**，不替换原有功能。

## Clarified Decisions

| 决策项 | 结论 |
|--------|------|
| 订单 Excel 格式 | **子订单格式**：每行一条子订单，对应一个商品，含 `商品ID`、`买家实付金额`（子订单级）等 15 个字段 |
| 走势数据来源 | 子订单中的「买家实付金额」字段（已是单品实付价，非整单合计） |
| 商品匹配方式 | 通过 `商品ID`（taobao_item_id）**精确匹配** `Product.taobao_item_id`，无需文本模糊匹配 |
| 多商品订单问题 | **不存在**：新格式每行已是单一商品的子订单，无需分摊逻辑 |
| 价格口径 | 仅使用「交易成功」状态的子订单 |
| 退款子订单 | 排除 `退款金额` 字段不为 `"无退款申请"` 的子订单（该字段为字符串，非数字） |
| 时间轴 | 使用 `订单创建时间` 作为价格点的时间坐标 |
| 默认展示区间 | 最近 90 天；用户可手动切换时间范围 |
| 走势图布局 | 独立新增图表区域，与快照走势图上下排列 |
| 同日多笔聚合 | 每笔子订单显示为独立数据点，不聚合 |
| Y 轴价格口径 | `买家实付金额 ÷ 购买数量`（**单件均价**），购买数量为 1 时结果与原值相同 |
| 导入无效行处理 | 跳过无效行（`商品ID` 为空或金额无法解析），计入 `errors` 统计，其余继续导入 |
| 子订单导入 UI | **仅支持子订单格式**，新建独立导入入口，不兼容旧主订单格式 |
| API 数据点上限 | 最多返回 **1000 个数据点**，超出时截断并在响应中标注 `truncated: true` |
| 图表类型 | **散点图 + 趋势线**（默认）：每笔子订单为独立散点，叠加线性回归趋势线；支持切换为**折线图模式**，按 SKU 分组连线 |
| SKU 颜色区分 | 散点图和折线图均按 `商品属性`（SKU 规格，如颜色/尺寸）分配不同颜色，同一 SKU 的点颜色一致；图表附带图例说明各颜色对应 SKU |
| 图表类型切换 | 详情页走势图区域提供「散点图 / 折线图」切换按钮（Toggle），切换时保留当前时间范围筛选状态 |
| 时间显示时区 | 使用**浏览器本地时间**展示，不使用服务器 UTC 时间（前端负责时区转换） |
| 购买数量为 0 时 | 单件均价直接显示为 **¥0.00**，不跳过该子订单，不报错 |

## Order Excel 字段说明（新格式）

新格式订单 xlsx 每行为一条**子订单**，包含以下字段：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `子订单编号` | string | 子订单唯一 ID（导入主键） |
| `主订单编号` | string | 主订单 ID（可多个子订单共享） |
| `商品标题` | string | 商品名称（冗余，主要用于展示） |
| `商品价格` | float | 商品标价（非实付） |
| `购买数量` | int | 该子订单购买数量 |
| `商品属性` | string | 规格属性（如颜色、尺寸） |
| `订单状态` | string | 枚举：交易成功 / 交易关闭 / 买家已付款,等待卖家发货 / 卖家已发货，等待买家确认 |
| `支付单号` | string | 支付凭证号 |
| `买家实付金额` | float | **该子订单的实际支付金额**（核心价格字段） |
| `退款金额` | string | `"无退款申请"` 或 数字字符串（如 `"23.52"`） |
| `订单创建时间` | datetime | 下单时间（价格走势 X 轴） |
| `订单付款时间` | datetime | 付款时间 |
| `淘鲜达渠道` | string | 渠道标识 |
| `商品ID` | string | **淘宝商品 ID（精确匹配 `Product.taobao_item_id`）** |
| `分阶段信息` | string/None | 分期信息（一般为空） |

## Data Model Change — Order 表重构

> **重要**：新订单 Excel 格式与现有 `Order` 数据模型**不兼容**，需要对 `Order` 表进行重构。

### 现有 Order 模型（旧）

旧格式基于**主订单**，`buyer_paid` 为整单合计，无商品 ID 字段，通过 `product_title` 文本识别商品。

### 新 Order 模型（子订单格式）

```
SubOrder
  id              : int (PK, autoincrement)
  sub_order_id    : str (unique, 子订单编号)
  main_order_id   : str (主订单编号)
  taobao_item_id  : str (index, 商品ID — 与 Product.taobao_item_id 精确匹配)
  product_title   : str (商品标题，展示用)
  product_price   : float (商品标价)
  quantity        : int (购买数量)
  product_attr    : str (商品属性)
  status          : str (订单状态)
  payment_id      : str (支付单号)
  buyer_paid      : float (买家实付金额，子订单级别)
  refund_amount   : str (退款金额字符串，"无退款申请" 或 金额字符串)
  created_at      : datetime (订单创建时间)
  paid_at         : datetime (订单付款时间)
  imported_at     : datetime (导入时间)
```

### 迁移策略

- 新建 `SubOrder` 表，与现有 `Order` 表**并存**（不删除旧表，保证现有功能不中断）。
- 价格走势功能完全基于 `SubOrder` 表查询。
- 后续可在专项迁移任务中评估是否合并或废弃旧 `Order` 表。

## User Scenarios & Testing

### User Story 1 - 在商品详情页查看订单实付价格走势 (Priority: P1)

作为卖家，当我在商品列表页点击某商品进入详情页后，我可以看到该商品基于历史订单的实付价格走势折线图，从而了解顾客实际成交价格随时间的变化情况。

**Why this priority**: 这是本次功能的核心价值——通过真实成交数据（而非标价快照）反映商品的实际售价趋势，是卖家定价决策的重要参考。

**Independent Test**: 导入包含 `商品ID = 844555963059` 子订单的 xlsx（含多个不同 `商品属性` 值），进入对应商品详情页，确认走势图（散点图模式）中不同 SKU 的数据点显示不同颜色，切换为折线图模式后各 SKU 以各自颜色连线，且数据点数量与导入的「交易成功」且无退款子订单数量一致。

**Acceptance Scenarios**:

1. **Given** 已导入子订单，且部分子订单的 `商品ID` 匹配当前商品的 `taobao_item_id`，**When** 我进入该商品详情页，**Then** 详情页显示「订单实付价格走势」图表区域（默认散点图模式），X 轴为订单创建时间，Y 轴为单件均价（元），每个有效子订单对应一个散点，**不同 `商品属性`（SKU）的散点显示不同颜色**，图表附带 SKU 颜色图例。
2. **Given** 散点图已显示，**When** 我将鼠标悬停在某数据点，**Then** 显示该子订单的创建时间、单件均价（买家实付金额 ÷ 购买数量）、商品属性（规格）、SKU 颜色标识的 Tooltip。
3. **Given** 已导入子订单，但当前商品的 `taobao_item_id` 在子订单表中无匹配记录，**When** 我进入该商品详情页，**Then** 图表区域显示空状态提示：「暂无匹配订单数据，无法展示价格走势」。
4. **Given** 价格走势图已显示，**When** 我切换时间范围（近 30 天 / 近 90 天 / 全部），**Then** 图表数据根据选定时间范围刷新，仅展示该时段内的子订单数据点，SKU 颜色映射不变。
5. **Given** 散点图模式下有多个 SKU 的数据点，**When** 我点击图表右上角的「折线图」切换按钮，**Then** 图表切换为折线图模式：每个 SKU 的数据点按时间排序后以对应颜色连线，趋势线保持可见；点击「散点图」按钮可切换回来。
6. **Given** 某 SKU 仅有 1 个数据点，**When** 处于折线图模式，**Then** 该 SKU 仍以对应颜色显示单独的点（无法连线），不报错。

### User Story 2 - 导入子订单 xlsx 文件 (Priority: P1)

作为卖家，我可以通过数据导入页面上传新格式（子订单格式）的淘宝订单 xlsx，系统将数据存入 `SubOrder` 表供走势图使用。

**Why this priority**: 走势图的数据来源依赖子订单导入；导入功能是数据管道的第一步。

**Independent Test**: 上传 `ExportOrderList*.xlsx`，确认系统成功解析 15 列（含 `商品ID`），将子订单写入 `sub_orders` 表，并返回导入数量统计。

**Acceptance Scenarios**:

1. **Given** 上传符合新格式的 xlsx，**When** 导入完成，**Then** 系统返回 `{imported, updated, skipped, errors}` 统计，且 `sub_orders` 表中可查到对应记录。
2. **Given** xlsx 缺少必填列（如 `商品ID` 或 `买家实付金额`），**When** 上传该文件，**Then** 系统返回 422 错误，并列出缺少的列名。
3. **Given** 同一 `子订单编号` 再次导入，**When** 导入执行，**Then** 系统更新已有记录（upsert），不重复插入，`updated` 计数增加。

---

### User Story 3 - 商品详情页价格走势图布局 (Priority: P2)

作为卖家，在商品详情页中，我可以分别查看「快照标价走势」和「订单实付价格走势」两个独立图表，两者上下排列，无需切换。

**Acceptance Scenarios**:

1. **Given** 商品既有快照数据也有订单数据，**When** 进入详情页，**Then** 页面从上到下显示：商品信息 → 快照价格走势图 → 订单实付价格走势图。
2. **Given** 商品只有快照数据没有订单数据，**When** 进入详情页，**Then** 快照走势图正常显示，订单走势图区域显示空状态。

---

### Edge Cases

- 当 `sub_orders` 表为空（尚未导入任何子订单）时，商品详情页的订单走势图区域显示「暂无订单数据，请先导入订单文件」。
- 当子订单的 `退款金额` 字段不为 `"无退款申请"`（含数字字符串如 `"23.52"`）时，该子订单**排除**在走势数据之外。
- 当同一商品同一天有多笔子订单时，每笔子订单均作为独立数据点显示在图表上（不聚合）。
- 当商品的 `taobao_item_id` 在商品表中存在但在子订单表中无记录时，显示空状态而非报错。

## Requirements

### Functional Requirements

- **FR-001**: 商品详情页 MUST 新增「订单实付价格走势」图表区域，位于现有快照价格走势图下方。
- **FR-002**: 系统 MUST 通过 `SubOrder.taobao_item_id = Product.taobao_item_id` 精确匹配，从 `sub_orders` 表筛选出该商品的有效子订单（`状态 = 交易成功` 且 `退款金额 = "无退款申请"`）。
- **FR-003**: 走势图 MUST 以 `订单创建时间` 为 X 轴，以**单件均价**（`买家实付金额 ÷ 购买数量`，单位：元）为 Y 轴，每笔有效子订单对应一个独立数据点；数据点 MUST 按 `商品属性`（SKU）分组，每个 SKU 分配不同颜色，图表附带颜色图例。
- **FR-004**: 走势图 MUST 提供时间范围筛选，默认展示近 90 天，支持近 30 天 / 近 90 天 / 全部三个选项。
- **FR-005**: 鼠标悬停于散点时，MUST 显示包含 `订单创建时间`、`单件均价`、`购买数量`、`商品属性` 的 Tooltip。
- **FR-006**: 匹配到的有效子订单为 0 时，MUST 显示空状态提示，说明无数据原因。
- **FR-007**: 走势图 MUST 与商品详情页其他内容（名称、当前价格、快照走势）在同一页面展示，无需额外导航。
- **FR-008**: 后端 MUST 提供 `GET /api/products/{id}/order-price-series` 接口，接受可选 `days` 参数（30/90/all），返回匹配子订单的时间-单件均价序列，最多 1000 条，超出时响应体含 `truncated: true`。
- **FR-009**: 后端 MUST 提供独立的子订单导入接口，**仅支持新子订单格式 xlsx**（15 列，含 `商品ID`），存入 `sub_orders` 表，以 `子订单编号` 为幂等键做 upsert；导入时跳过 `商品ID` 为空或金额无法解析的无效行，将其计入响应的 `errors` 字段。
- **FR-010**: `退款金额` 字段为字符串类型，系统 MUST 将值不为 `"无退款申请"` 的子订单视为有退款，排除在走势数据之外。
- **FR-011**: 走势图 MUST 在散点图之上叠加**线性回归趋势线**，直观反映整体价格走势方向（纯视觉辅助，无需交互）；折线图模式下趋势线同样保持显示。
- **FR-012**: 走势图区域 MUST 提供「散点图 / 折线图」切换控件（Toggle），默认为散点图模式；切换时保留当前时间范围筛选状态，SKU 颜色映射不变。
- **FR-013**: 折线图模式下，MUST 将每个 SKU 的数据点按 `订单创建时间` 升序排列后连线；仅有单个数据点的 SKU 显示为孤立点，不报错。
- **FR-014**: 后端 `GET /api/products/{id}/order-price-series` 响应中每个数据点 MUST 包含 `product_attr` 字段，供前端按 SKU 着色分组，无需额外接口。

### Key Entities

- **Product（商品）**: 具有唯一的 `taobao_item_id` 和 `name`，是价格走势图的查询主体。
- **SubOrder（子订单）**: 新表，每行对应一个商品的成交记录，包含 `taobao_item_id`（精确关联商品）、`buyer_paid`（子订单实付金额）、`created_at`（订单时间）、`status`、`refund_amount`（字符串）等字段。
- **OrderPriceSeries（价格数列）**: 由后端从 `SubOrder` 聚合生成，表示特定商品在一段时间内的子订单实付价格序列，每个数据点包含 `product_attr`（SKU）字段，作为走势图的响应数据结构。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户从商品列表点击进入商品详情页后，订单价格走势图在 2 秒内完成渲染。
- **SC-002**: 走势图显示的散点数量与 `sub_orders` 表中匹配该商品的有效子订单数量完全一致（上限 1000 点；超出时响应含 `truncated: true`）。
- **SC-003**: 时间范围切换后，图表数据在 1 秒内刷新，无需重新加载整个页面。
- **SC-004**: 对于无匹配子订单的商品，空状态提示可读且说明原因，不显示报错信息。
- **SC-005**: 子订单 xlsx 导入（2391 行）在 10 秒内完成，返回正确的 `{imported, updated, skipped, errors}` 统计。
- **SC-006**: 趋势线可见，方向与散点整体走势一致（视觉验证，无精度要求）。
- **SC-007**: 当商品有 ≥2 个不同 SKU 时，散点图和折线图模式下各 SKU 颜色不同且图例可读，颜色数量与 SKU 种类数一致。
- **SC-008**: 图表类型切换（散点图 ↔ 折线图）在 300ms 内完成视觉切换，无网络请求。

## Assumptions

- 淘宝订单 xlsx 格式固定为 15 列（`子订单编号` 到 `分阶段信息`），列名与字段说明表一致。
- `商品ID` 字段（淘宝 item_id）与 `Product.taobao_item_id` 格式一致（均为字符串，无需转换）。
- `退款金额` 字段为字符串类型：`"无退款申请"` 表示无退款，其他值（如 `"23.52"`）表示有退款金额。
- 本功能不修改现有快照价格走势图的任何逻辑，仅新增订单走势图区域和 `sub_orders` 表。
- 新 `SubOrder` 表与现有 `Order` 表**并存**，不迁移或删除旧 `Order` 数据。
- 移动端适配不在本次迭代范围内，仅保证桌面浏览器（1280px 以上）正常显示。
- 已有商品详情页路由（`/products/:id`）存在，本功能在该页面新增图表组件，不新增路由。
